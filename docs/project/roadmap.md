# STAGE 02.4.5-A — Mobile Fix Pack

## Статус: следующий этап

### Цель

Исправить mobile input и mobile layout проблемы после Stage 02.4.5.

### Основные проблемы

## 1. Build Confirm Bug

Симптом:
- клетка визуально выбрана;
- build overlay отображается;
- при нажатии “Построить” появляется сообщение “Сначала выбери клетку”;
- башня не строится.

Нужно проверить:
- pendingBuildTile;
- canvas tap;
- DOM button click;
- pointer events;
- z-index;
- сохранение выбранной клетки между tap по canvas и tap по кнопке.

---

## 2. Coordinate Mapping Instability

Симптом:
- выбранная клетка ощущается смещённой относительно пальца;
- особенно заметно на телефоне и планшете.

Нужно проверить:
- screenToWorld;
- screenToTile;
- camera.zoom;
- browser offsets;
- Safari viewport;
- safe-area.

---

## 3. Zoom Stabilization

Симптом:
- zoom работает;
- но можно увести масштаб в неудобное состояние;
- нижняя кнопка zoom остаётся “100%”, хотя фактический zoom меняется.

Нужно:
- стабилизировать min/max zoom;
- добавить нормальный reset;
- сделать нижний zoom label динамическим или убрать дублирование.

---

## 4. Codex Mobile Layout

Симптом:
- Codex на телефоне закрывает почти весь экран.

Нужно:
- уменьшить панель;
- сделать её компактнее;
- возможно, перевести Codex в отдельный режим / modal / drawer;
- отделить справку от основного gameplay area.

---

## 5. Landscape Layout

Симптом:
- в горизонтальном режиме панели перекрывают карту;
- wave status и controls занимают слишком много места.

Нужно:
- сделать отдельный landscape layout;
- перенести action buttons;
- уменьшить wave panel;
- освободить центр карты.

---

## 6. Control Placement

Симптом:
- кнопки “Башня”, “Волна”, “Codex”, “Меню” расположены неидеально для мобильного управления.

Предварительное направление:
- “Башня” и “Волна” ближе к правому пальцу;
- “Codex” и “Меню” отдельно, компактнее;
- speed / zoom controls сгруппировать аккуратнее;
- landscape и portrait должны иметь разные схемы.

---

# STAGE 02.5 — Recovery Economy & Infrastructure

## Статус: планируется после 02.4.5-A

После стабилизации mobile UX можно переходить к развитию игрового мира.

### Основная идея

Перейти от простого wave-defense к более живой RTS / survival economy.

Игровой цикл должен развиваться в сторону:

~~~text
волна → разрушения → сбор → ремонт → переработка → подготовка → новая волна
~~~

---

## Планируемые системы

### 1. Генераторы энергии

Нужно добавить способ увеличивать лимит энергии.

Пока энергия только ограничивает строительство башен.

Дальше нужны:
- генератор;
- энергосеть;
- рост power capacity;
- стоимость генераторов;
- защита энергетической инфраструктуры.

---

### 2. Гражданская инфраструктура

Появляются постройки не для боя:
- генераторы;
- склады;
- переработчики;
- ремонтные здания;
- ресурсные здания;
- логистические здания.

---

### 3. Обломки и salvage system

После уничтожения башен или врагов могут оставаться:
- обломки;
- лом;
- биомасса;
- детали;
- остатки энергии.

Они должны:
- лежать на карте;
- занимать место;
- собираться;
- перерабатываться;
- давать ресурсы.

---

### 4. Харвестеры / сборщики

Гражданские юниты:
- выезжают с базы;
- собирают обломки или биомассу;
- возвращают ресурсы на базу;
- работают между волнами.

---

### 5. Ремонт

Будущая система:
- башни могут получать повреждения;
- башни можно ремонтировать;
- разрушенные башни оставляют обломки;
- ремонт требует ресурсы и время.
