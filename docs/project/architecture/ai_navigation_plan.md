# AI Navigation Plan — CORE FRONTIER

## Назначение документа

Этот файл описывает navigation/retrieval layer проекта CORE FRONTIER.

Документ НЕ является roadmap.

Документ НЕ является giant AI archive.

Документ описывает:

как AI должен безопасно ориентироваться в проекте.

Важно:

этот файл сохраняет planning/history context Stage 03.1,
но после Stage 03.3B также фиксирует текущую active YAML navigation reality.

---

## Почему появился navigation layer

Stage 03.1 подтвердил проблемы giant markdown workflow.

Подтверждены риски:

- connector truncation;
- incomplete visibility;
- unsafe overwrite;
- giant-file instability;
- retrieval degradation;
- navigation complexity;
- partial repository visibility.

Следовательно:

AI больше не должен ориентироваться только через giant markdown files.

---

## Human memory vs AI navigation

Подтверждено разделение:

### Human memory layer

    docs/project/

Содержит:

- stages;
- reports;
- architecture docs;
- roadmap;
- reasoning;
- project history;
- operational context.

Назначение:

долговременная human-readable память проекта.

---

### AI navigation layer

Active layer:

    ai/

Текущие active files после Stage 03.3B:

    ai/current_status.yml
    ai/docs_map.yml

Назначение:

- compressed navigation;
- retrieval shortcuts;
- current repository state visibility;
- topology/navigation mapping;
- safe entrypoints.

Главная цель:

ускорить navigation/retrieval workflow без дублирования giant history layer.

---

## AI navigation layer НЕ должен

AI navigation layer НЕ должен становиться:

- giant archive;
- duplicate history layer;
- full reasoning dump;
- replacement для docs/project/;
- giant autogenerated documentation layer;
- runtime automation engine;
- governance engine.

Полный reasoning/history должен оставаться в human memory layer.

---

## Текущая структура ai/

Текущая active YAML navigation structure:

    ai/current_status.yml
    ai/docs_map.yml

ai/current_status.yml:

- фиксирует current stage/status;
- фиксирует runtime/surface/navigation state;
- фиксирует deferred layers;
- помогает быстро определить safe next direction.

ai/docs_map.yml:

- фиксирует architecture/roadmap entrypoints;
- фиксирует runtime topology;
- фиксирует script order;
- фиксирует repository surface relationship;
- помогает быстро ориентироваться в repository structure.

Важно:

эти YAML files являются compressed navigation layer,
а не full documentation replacement.

## workflow.md as operational authority

Operational workflow authority document:

    docs/project/architecture/workflow.md

workflow.md фиксирует:

- inspection-first discipline;
- bounded pass discipline;
- full-file visibility requirement;
- no unsafe overwrite from memory;
- audit/sync/verification pass separation;
- post-mutation verification discipline;
- connector read/write split realities;

- commit title/body language discipline.

## Compressed navigation principle

Navigation artifacts должны быть:

- bounded;
- compressed;
- retrieval-oriented;
- navigation-oriented;
- index-oriented;
- connector-safe.

Нежелательно:

- giant markdown files;
- giant generated reports;
- duplicated reasoning;
- duplicated stage history.

---

## Retrieval-safe architecture

CORE FRONTIER теперь должен развиваться как:

- repository-aware project;
- retrieval-aware project;
- connector-aware project;
- visibility-aware project.

AI visibility становится engineering constraint.

---

## Navigation-safe workflow

Navigation layer должен обновляться:

- isolated passes;
- bounded updates;
- targeted modifications;
- comments-only updates where possible;
- post-sync verification passes.

Нельзя:

- giant regeneration;
- repo-wide rewrite;
- giant AI sync passes;
- overwrite from memory.

---

## Visibility integrity rules

Подтверждённый принцип:

    visibility uncertainty = stop condition

Если:

- connector truncation detected;
- file visibility incomplete;
- overwrite unsafe;
- dependency visibility unclear;

AI обязан:

- остановить rewrite;
- перейти в inspection/report mode;
- запросить safer workflow;
- использовать bounded patches.

## Navigation layer и runtime

AI navigation layer не должен менять runtime behavior.

Navigation layer:

- описывает;
- индексирует;
- ускоряет navigation;
- помогает retrieval;
- помогает inspection workflow.

Но НЕ должен:

- владеть gameplay logic;
- менять runtime contracts;
- влиять на execution;
- внедрять automation tooling.
