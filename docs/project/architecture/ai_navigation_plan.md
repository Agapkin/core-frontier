# AI Navigation Plan — CORE FRONTIER

## Назначение документа

Этот файл описывает будущий navigation/retrieval layer проекта CORE FRONTIER.

Документ НЕ является roadmap.

Документ НЕ является giant AI archive.

Документ описывает:

как AI должен безопасно ориентироваться в проекте.

---

## Почему появился navigation layer

Stage 03.1 подтвердил проблемы giant markdown workflow.

Подтверждены риски:

- connector truncation;
- incomplete visibility;
- unsafe overwrite;
- giant-file instability;
- retrieval degradation;
- navigation complexity;
- partial repository visibility.

Следовательно:

AI больше не должен ориентироваться только через giant markdown files.

---

## Human memory vs AI navigation

Подтверждено разделение:

### Human memory layer

    docs/project/

Содержит:

- stages;
- reports;
- architecture docs;
- roadmap;
- reasoning;
- project history;
- operational context.

Назначение:

долговременная human-readable память проекта.

---

### AI navigation layer

Предварительный кандидат:

    ai/

Назначение:

- compressed navigation;
- retrieval shortcuts;
- subsystem maps;
- runtime maps;
- contracts index;
- current status visibility;
- safe entrypoints.

Главная цель:

ускорить navigation/retrieval workflow.

---

## AI navigation layer НЕ должен

AI navigation layer НЕ должен становиться:

- giant archive;
- duplicate history layer;
- full reasoning dump;
- replacement для docs/project/;
- giant autogenerated documentation layer.

Полный reasoning/history должен оставаться в human memory layer.

---

## Предварительная структура ai/

Предварительно рассматриваются:

    ai/README.md
    ai/runtime_map.md
    ai/docs_map.md
    ai/contracts.md
    ai/current_status.md

Важно:

Stage 03.1 НЕ утверждает финальную структуру ai/.

Это preliminary navigation proposal.

помочь retrieval/navigation.

---

## ai/contracts.md

Потенциальная роль:

- runtime contracts index;

- dangerous combined-change zones.

НЕ full architecture rewrite.

Потенциальная роль:

---

## Compressed navigation principle

Navigation artifacts должны быть:

- bounded;
- compressed;
- retrieval-oriented;
- navigation-oriented;
- index-oriented;
- connector-safe.

Нежелательно:

- giant markdown files;
- giant generated reports;
- duplicated reasoning;
- duplicated stage history.

---

## Retrieval-safe architecture

CORE FRONTIER теперь должен развиваться как:

- repository-aware project;
- retrieval-aware project;
- connector-aware project;
- visibility-aware project.

AI visibility становится engineering constraint.

---

## Navigation-safe workflow

Navigation layer должен обновляться:

- isolated passes;
- bounded updates;
- targeted modifications;
- comments-only updates where possible.

Нельзя:

- giant regeneration;
- repo-wide rewrite;
- giant AI sync passes.

---

## Visibility integrity rules

Подтверждённый принцип:

    visibility uncertainty = stop condition

Если:

- connector truncation detected;
- file visibility incomplete;
- overwrite unsafe;
- dependency visibility unclear;

AI обязан:

- остановить rewrite;
- перейти в inspection/report mode;
- запросить safer workflow;
- использовать bounded patches.

---

## Future AI-readable markup

Stage 03.1 не внедряет AI-readable markup.

Но подтверждает foundation для future:

- comments-only AI-readable layer;
- navigation markers;
- contracts visibility;
- runtime ownership hints;
- safe retrieval hints.

Важно:

markup должен быть compatibility-safe и bounded.

---

## Navigation layer и runtime

AI navigation layer не должен менять runtime behavior.

Navigation layer:

- описывает;
- индексирует;
- ускоряет navigation;
- помогает retrieval;
- помогает inspection workflow.

Но НЕ должен:

- владеть gameplay logic;
- менять runtime contracts;
- влиять на execution.

---

## Главный вывод

Будущий AI navigation layer нужен не для giant AI memory.

Он нужен для:

- safe retrieval;
- bounded navigation;
- connector-safe workflow;
- runtime visibility;
- architecture visibility;
- safer repository evolution.

Главный принцип:

navigation layer должен быть компактным,
а human memory layer — подробным.
