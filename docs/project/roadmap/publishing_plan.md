# Publishing Plan — CORE FRONTIER

## Назначение документа

Этот файл фиксирует будущие publishing/platform направления проекта CORE FRONTIER.

Документ НЕ является:

- active operational roadmap;
- architecture document;
- gameplay roadmap;
- immediate execution plan.

Главная задача:

вынести publishing/platform direction отдельно от runtime development и architecture stabilization.

---

## Почему publishing roadmap вынесен отдельно

Подтверждено:

publishing direction имеет собственные задачи:

- deployment;
- platforms;
- distribution;
- marketplace visibility;
- release workflow;
- public packaging;
- external presentation.

Эти задачи не должны смешиваться с:

- runtime stabilization;
- architecture workflow;
- gameplay expansion;
- AI navigation planning.

---

## Текущий статус publishing layer

Текущий статус:

- проект пока НЕ находится в release-ready состоянии;
- architecture stabilization ещё продолжается;
- gameplay evolution временно paused;
- publishing workflow пока planning-only;
- deployment architecture ещё не финализирована.

Подтверждено:

сейчас приоритетом является stabilizing repository/runtime workflow before public expansion.

---

## Подтверждённые publishing направления

Потенциальные publishing направления:

- GitHub Pages deployment;
- browser-first distribution;
- PWA direction;
- mobile browser support;
- standalone packaging;
- future platform ports;
- playable public builds;
- demo builds;
- testing builds;
- closed testing workflow.

---

## GitHub Pages direction

Подтверждено:

GitHub Pages рассматривается как primary lightweight deployment direction.

Причины:

- минимальные infrastructure costs;
- simple deployment workflow;
- browser-native accessibility;
- быстрый iteration cycle;
- repository integration.

Важно:

deployment workflow должен оставаться compatibility-safe и bounded.

---

## Browser-first direction

CORE FRONTIER сейчас ориентирован на:

- browser runtime;
- canvas rendering;
- responsive UI;
- mobile browser interaction.

Следовательно:

browser-first workflow остаётся главным publishing direction.

---

## PWA direction

Потенциальное направление:

Progressive Web App (PWA).

Преимущества:

- installation-like experience;
- mobile-friendly workflow;
- lightweight distribution;
- browser compatibility;
- reduced platform friction.

Но:

PWA direction пока НЕ является active implementation task.

---

## Public build strategy

Будущие public builds должны быть:

- bounded;
- stable;
- testable;
- compatibility-safe;
- mobile-aware.

Не рекомендуется:

- публиковать unstable giant experimental builds;
- смешивать runtime refactor и public releases;
- выпускать builds без visibility-safe workflow.

---

## Testing workflow direction

Подтверждены будущие testing directions:

- internal builds;
- mobile interaction testing;
- balance testing;
- regression testing;
- bounded gameplay testing;
- compatibility testing.

Особенно важно:

- build flow;
- mobile input;
- restart/retry lifecycle;
- render/update order;
- UI visibility;
- responsive layout.

---

## Marketplace/platform direction

Потенциальные future directions:

- itch.io;
- browser game platforms;
- PWA catalogs;
- standalone web portal;
- future app packaging.

Но:

platform expansion пока secondary priority относительно architecture/runtime stabilization.

---

## UI/Presentation direction

Будущие presentation directions:

- cleaner UI presentation;
- onboarding flow;
- simplified player entry;
- Codex improvements;
- tutorial systems;
- public-facing HUD cleanup.

Важно:

presentation improvements должны быть совместимы с bounded runtime evolution workflow.

---

## AI/navigation impact on publishing

Подтверждено:

future publishing workflow теперь зависит от:

- repository stability;
- visibility-safe evolution;
- bounded documentation;
- connector-safe workflow;
- compatibility-safe runtime changes.

Следовательно:

stable development workflow теперь является частью release readiness.

---

## Safe release principles

Будущие release passes должны быть:

- staged;
- bounded;
- regression-aware;
- compatibility-safe;
- mobile-tested;
- visibility-safe.

Запрещено:

- giant release rewrites;
- unstable deployment refactors;
- uncontrolled public builds.

---

## Long-term direction

CORE FRONTIER рассматривается как:

- evolving strategy game;
- expandable browser platform;
- modular gameplay system;
- long-term iterative project.

Следовательно:

publishing strategy должна поддерживать long-term staged evolution, а не one-shot release model.

---

## Общий вывод

Publishing roadmap существует отдельно от:

- architecture stabilization;
- active operational workflow;
- gameplay expansion roadmap.

Подтверждено:

public growth проекта должен происходить только после stabilizing internal repository/runtime workflow.

Главный принцип:

сначала стабильная evolution foundation,
потом масштабирование и public distribution.
