Принципы архитектуры

1. Минимальный корень проекта

В корне находятся только:

* README.md
* index.html
* основные папки проекта

Это позволяет не превращать корень репозитория в свалку.

⸻

2. Разделение по смыслу

Текущая структура:

* css/ — визуальное оформление
* js/ — игровая логика
* docs/ — документация

⸻

3. Документирование этапов

Каждый значимый этап фиксируется отдельным stage-файлом.

Формат:

* цель этапа
* что планировалось
* что реализовано
* что протестировано
* какие проблемы выявлены
* какой задел уходит в следующий этап

⸻

4. История через GitHub

Старые версии не сохраняются отдельными файлами.

История хранится через:

* commits
* GitHub history
* stage-документацию

⸻

5. Один game.js до предела удобства

Пока вся игровая логика остаётся в js/game.js.

Причина:

* проект редактируется вручную через GitHub
* один файл проще заменять на мобильном устройстве
* быстрые итерации важнее ранней декомпозиции

Но файл должен оставаться структурированным по секциям.

6. Подготовка к модульности

В будущем js/game.js нужно будет разделить на модули:

Текущее ядро включает:

* tactical combat
* grid map
* waves
* resource pressure
* energy limit
* retry loop
* difficulty profiles
* tower selection
