# Архитектура проекта CORE FRONTIER

## Структура репозитория

```text
core-frontier/

README.md

└── style.css

js/
└── game.js

docs/
├── design/
│   └── mechanics.md

Назначение файлов

README.md

Главное описание проекта.

Содержит:

* концепцию игры
* цели проекта
* этапы развития
* описание механик

⸻

index.html

Главная точка запуска проекта.

Отвечает за:

* подключение CSS
* подключение JS
* создание canvas
* базовую HTML-структуру интерфейса

⸻

css/style.css

Основной визуальный стиль проекта.

Отвечает за:

* оформление интерфейса
* кнопки
* HUD
* цвета
* layout
* адаптацию под экран

⸻

js/game.js

Главный игровой файл.

Содержит:

* цикл игры
* отрисовку
* врагов
* башни
* стрельбу
* карту
* камеру
* управление
* волны
* ресурсы
* обработку логики

⸻

Документация проекта

docs/design/

Принципы архитектуры

1. Минимальный корень репозитория

В корне находятся только:

* README
* index.html
* основные папки

Это упрощает навигацию.

⸻

2. Разделение логики

Код разделяется по типам:

* JS → логика
* CSS → визуал
* docs → документация

⸻

3. Документирование этапов

Каждый этап фиксируется отдельным stage-файлом.

Это позволяет:

* сохранять историю разработки
* анализировать изменения
* отслеживать прогресс
* возвращаться к прошлым решениям

⸻

4. GitHub как система версий

История проекта хранится через:

* commits
* branch
* GitHub history

Отдельные backup-файлы не используются.

⸻

5. Подготовка к масштабированию

Структура должна позволять:

* добавлять новые JS-модули
* подключать новые механики
* расширять UI
* создавать новые режимы игры
* выносить системы в отдельные файлы
